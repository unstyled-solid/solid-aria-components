## Smallest consequences for R's current boundary

1. **Separate lifetime from publication explicitly.** The TableInner owner should survive same-structure collection revisions, while its collection-dependent computations receive the latest completed collection. Kobalte's strongest transferable idea is this separation, not its DOM collection algorithm.
2. **Keep readiness and updates observable inside that surviving owner.** The 75px regression means the stable facade was insufficient; it does not show which downstream dependency was lost. A design must specify where initial collection readiness, column metadata, and measured width enter tracked computations. No claim that stable ownership alone repairs widths.
3. **Only then address immutable item identity.** Use the existing RAC rendered/node-key precedence at the row/item boundary; RC13 custom-keyed For can retain owners while an accessor advances the node value. Do not snapshot that accessor in setup, cache old JSX/DOM, or change source algorithms to fit a registry.
4. **Treat removal separately from metadata replacement.** A cleanup/re-registration bridge must not transiently clear the existing selected/focused key or reorder state as though the item were permanently removed. Source RAC removal/selection semantics remain authoritative; Kobalte's post-DOM registration lifecycle does not establish them.
5. **Keep the existing first gate.** The unchanged Height−50 case must first obtain the correct initial widths and retain the captured resizer through width commit/pointerUp. This reference adds no tests, acceptance gates, or verified implementation claims.
